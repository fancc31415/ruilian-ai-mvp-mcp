## 当前版本的关键设计决策

1. **LLM 降级机制**：所有依赖LLM的环节（BP解析、匹配理由生成）都有关键词规则/模板兜底，
   即使没配置API Key也能跑通完整流程看到效果，只是质量会打折扣。方便你先看流程对不对，
   再决定要不要花钱调LLM。

2. **打分权重是拍的，不是学出来的**：赛道40% / 阶段30% / 规模20% / 其他10%，这是我根据BP里
   提到的"多维度打分"逻辑给的**初始值**，不是经过验证的最优解。等有了真实撮合成交/反馈数据，
   这里应该换成能根据历史数据调权重（甚至训练一个轻量排序模型）的版本。

3. **机构库是公开信息拼的种子库**：64家主流机构，赛道/阶段/规模字段是我根据公开报道和常识
   估的，精度有限（比如"经纬创投偏好B轮还是C轮"这种细节，没有真实台账很难准）。这是目前
   MVP里最需要你补充真实数据的地方——机构库的准确度直接决定匹配报告的可信度。

## 下一步建议（不是马上做，是列个优先级供你参考）

- [ ] 机构库数据校准：把你手上真实成交过的机构信息（哪怕只有20-30家）录进去替换种子数据，
      准确度会立刻好很多
- [ ] BP解析支持扫描版PDF（现在纯图片PDF提取不到文字，需要接OCR）
- [ ] 报告导出加PDF/Word格式（现在只有Markdown）
- [ ] 匹配理由生成加缓存，避免同一份BP重复点"生成报告"时重复调用LLM花钱
- [ ] 项目收费流程怎么接（现在完全没做支付/计费逻辑）

### Demo 讲解

> "这是我们做的智能匹配MVP：企业上传BP，AI自动提取赛道、阶段、融资金额这些关键信息，
> 对照我们收录的机构数据库做多维度打分，几秒内输出Top10-15家最匹配的机构，每家还附带
> 匹配理由和具体的沟通建议——这个流程原来靠人工至少要2-3天，现在压缩到几分钟。
> 现在你看到的匹配逻辑和机构数据是种子版本，下一步我们会用真实的撮合成交反馈去校准
> 匹配权重和数据准确度。"

**诚实是加分项**：按实话说"这是基于规则的第一版，权重是我们按行业经验设的初始值，团队清楚知道要靠真实成交数据去迭代校准，这也是
我们要融这轮种子资金重点投入的地方"。评委见得多，装准比承认还在验证阶段更容易扣分。

## 已知限制

- 没做用户登录/多租户，现在是单机单会话演示版本
- 机构库是内存中一次性加载的JSON，没有做后台管理界面（BP里提到"后续再做后台管理"，这版先跳过）
- LLM调用没做重试和限流保护，生产环境用之前建议加上
